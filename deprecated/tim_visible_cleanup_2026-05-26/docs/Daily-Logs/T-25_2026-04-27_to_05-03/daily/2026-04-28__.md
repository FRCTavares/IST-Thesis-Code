# Daily Plan - 2026-04-28 (Day 28) - Implementation Focus

## Goal

Improve flight-session data capture, add an offline bag-to-overlay-video path, and make live target inspection/selection available from the `live-stack>` prompt.

## Context

### Baseline before changes

- `start_live_stack.sh` only had a basic rosbag hook.
- Bags were written under the live-stack log folder instead of being treated as first-class experiment artefacts.
- There was no dedicated flight-video workflow.
- There was no offline overlay-video renderer.
- Terminal interaction only supported `status`, `clear`, and `stop`.
- `tools/` mixed launchers, analysis scripts, validation utilities, camera probes, setup scripts, and experiments.

### Constraints

- Do not record `/camera/image_raw` during normal flight sessions because it is too heavy.
- Keep the live perception and control stack lightweight.
- Use `/camera/dashboard` as the recorded video stream.
- Preserve MCAP bag format.
- Keep generated bags and rendered videos out of Git.
- Avoid breaking existing live-stack usage.

### Tracker baseline implementation and validation

- Verified the existing SORT implementation as a correct SORT-style baseline:
  - 7D Kalman state `[cx, cy, area, aspect, vx, vy, v_area]`.
  - IoU-Hungarian association.
  - `max_age` / `min_hits` lifecycle.
  - Optional centre gating retained as a live embedded-system modification.

- Reworked OC-SORT into a reference-aligned implementation:
  - Added observation-centric momentum, OCM.
  - Added observation-centric re-update, ORU, through virtual observations after missed detections.
  - Used reference-style defaults for benchmark mode:
    - `iou_threshold=0.3`
    - `max_age=30`
    - `min_hits=3`
    - `delta_t=3`
    - `inertia=0.2`
  - Kept live-control tuning possible through launcher parameters.

- Reworked ByteTrack into a reference-aligned implementation:
  - Replaced the SORT-style Kalman state with the ByteTrack/DeepSORT-style 8D `xyah` Kalman state:
    - `[x, y, aspect, h, vx, vy, v_aspect, v_h]`
  - Implemented high-score first association.
  - Implemented low-score second association.
  - Implemented unconfirmed track handling.
  - Implemented tracked/lost/removed state pools.
  - Implemented duplicate-track cleanup.
  - Verified low-confidence rescue behaviour with a synthetic test.

- Reworked DeepSORT into a faithful MARS-based implementation:
  - Removed the non-faithful colour-histogram fallback path.
  - Required `mars-small128.pb` as the appearance model.
  - Kept the faithful DeepSORT components:
    - 8D Kalman state.
    - Matching cascade.
    - Mahalanobis gating with chi-square threshold.
    - Nearest-neighbour cosine metric.
    - Feature gallery with `nn_budget`.
    - Tentative/confirmed/deleted lifecycle.
    - IoU fallback for unconfirmed and recent tracks.
  - Added live-stack support for passing the MARS model path:
    - `REID_MODEL_PATH="$THESIS_ROOT/models/reid/mars-small128.pb"`
  - Updated tracker launch environment so the ROS tracker node can see TensorFlow from the project `.venv`.

- Updated `tools/start_live_stack.sh`:
  - Added default `REID_MODEL_PATH`.
  - Added DeepSORT-specific startup logging.
  - Passed faithful DeepSORT parameters:
    - `reid_model_path`
    - `reid_batch_size`
    - `max_cosine_distance`
    - `max_iou_distance`
    - `nn_budget`
    - `only_position_gating`
  - Removed the old `reid_fallback_to_histogram` runtime parameter.
  - Added a fail-fast check for the DeepSORT ReID model path.

## Findings

### What worked

- `--record-video` successfully created MCAP bags under `artifacts/bags/live_camera/`.
- `flight_metadata.txt` captured run configuration and recorded topics.
- `/timing_tracker` was correctly recorded after forcing `TRACKER_PUBLISH_TIMING_BOOL=true` for video runs.
- Offline overlay rendering worked.
- The renderer exported native, 720p, and 1080p video sizes.
- Letterboxed 640x640 perception coordinates were mapped correctly onto the 640x360 dashboard stream.
- Tracks now render by default, which avoids duplicate detection and track boxes.
- Live terminal commands now support `ids`, `target <id>`, and `clear-target`.
- The tooling folder structure is cleaner and grouped by workflow.
- Syntax and compile checks passed after the reorganisation.

### Immediate observations

- The second smoke bag validated the expected message counts:
  - `/timing_tracker`: 359 messages
  - `/tracks`: 359 messages
  - `/detections`: 370 messages
  - `/camera/dashboard`: 416 messages
- Initial overlay boxes were vertically wrong because the perception/tracking coordinates were in 640x640 letterboxed space while `/camera/dashboard` was 640x360.
- The corrected render temporarily showed no boxes because of an indentation bug; fixing that restored track drawing.
- `--output-size 1280x720` and `--output-size 1920x1080` both work, but they upscale the recorded 640x360 source.
- For true 720p/1080p visual quality, `/camera/dashboard` must be recorded at a higher resolution during the live run.
- `ids` can time out if invoked before `/tracks` starts publishing; increasing the timeout to 4.0s helped.

### Regressions and caveats

- Installing the latest `opencv-python-headless` initially pulled `numpy 2.4.4`, which conflicted with Hailo requirements.
- The dependency set was repaired by pinning `numpy==1.26.4` and `opencv-python-headless==4.10.0.84`.
- `hailort` was not importable in the active `.venv`, but the live stack still started successfully with `hailo_direct`. Leave this alone unless live startup breaks.
- 1080p renders do not look like true 1080p because the recorded source is still 640x360.
