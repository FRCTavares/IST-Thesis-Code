## Where Latency Currently Is

Primary conclusion:
- The dominant issue is cadence jitter (pub_dt_ms), not per-frame compute.

Progress update:
- The tail is materially reduced versus the initial baseline (`pub_dt_ms` p95: 187.18 -> 135.05, p99: 276.05 -> 164.78).
- Throughput improved substantially (`/timing` Hz: 9.28 -> 14.97).

Evidence:
- infer_ms is low and stable (single-digit ms p95).
- e2e_det_ms remains moderate under the new profile (p95 ~44 ms with dashboard on at 30 FPS).
- pub_dt_ms tails are still the largest latency contributor, even after improvement.

Interpretation:
- Camera and inference can process frames, but frame delivery/publication cadence is bursty.
- Remaining lag is mostly scheduling/queueing/cadence instability around message publication and pipeline pacing.

## Dashboard reliability fixes landed (same day follow-up)

- Root cause: `web_video_server` subscribed with default QoS, incompatible with best-effort publisher reliability.

2. After stream restore, boxes were misaligned.

	- `/camera/image_raw`: `1280x720`
	- `/camera/dashboard`: `640x360`
	- `/detections` bbox coordinates: inference frame basis (`640x640`)
- Fix: dashboard bridge normalization set to `img_w=640`, `img_h=640` to match inference bbox basis.
- Result: overlay alignment corrected.
