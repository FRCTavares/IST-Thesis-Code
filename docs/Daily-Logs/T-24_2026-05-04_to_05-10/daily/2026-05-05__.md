# Daily Log - 2026-05-05 - TIM-V0 Implementation, Evaluation, and Recovery Hardening

## Goal

Advance the thesis novelty work by implementing and validating TIM-V0, a selected-target memory layer for RGB-only UAV person following.

The specific objective for the day was to move from a conceptual novelty plan to a working, testable, recordable, and analysable implementation.

---

## Context

The thesis problem is not generic multi-object tracking.

Generic MOT asks:

> Can all object identities be maintained?

This thesis asks:

> Can one operator-selected person be maintained as a stable, control-valid target under noisy detections, occlusion, temporary loss, and tracker ID reassignment?

Before today, target selection was mostly raw tracker-ID based. This meant that if the selected tracker ID disappeared, the target output could remain invalid even if the same physical person reappeared under a new tracker ID.

TIM-V0 was introduced to address this gap using lightweight temporal memory and geometric consistency.

---

## TIM-V0 Scope

TIM-V0 uses only lightweight cues:

- IoU consistency
- centre-distance consistency
- scale consistency
- confidence
- same-ID bonus
- ambiguity rejection
- state hysteresis

TIM-V0 does **not** use:

- learned appearance embeddings
- ROI re-detection
- detector retraining
- global MOT identity optimisation

This keeps V0 simple, fast, and suitable as the baseline novelty layer before TIM-V1 appearance support.

---

## TIM-V0 State Machine

Implemented states:

- `NO_TARGET`
- `LOCKED`
- `UNCERTAIN`
- `LOST`
- `REACQUIRED`

Implemented control modes:

- `NO_CONTROL`
- `NORMAL`
- `YAW_ONLY`
- `HOVER`
- `CONFIRM`

Control-validity policy:

```text
NO_TARGET   -> NO_CONTROL
LOCKED      -> NORMAL
UNCERTAIN   -> YAW_ONLY
LOST        -> HOVER
REACQUIRED  -> CONFIRM
```

### Target mirroring

Added automatic mirroring from dashboard-selected `/target`.

This means the operator only needs to use:

```text
target <id>
```

from the live-stack prompt. TIM automatically mirrors positive raw target IDs and initialises its memory.

This removed the manual need to publish:

```bash
ros2 topic pub --once /target_memory/select std_msgs/msg/UInt32 "{data: 1}"
```

### Control-safe output

Updated `/target_memory` to be conservative for controller-style consumers:

```text
visible/control-valid target -> publish id, bbox, score, quality
not visible or invalid       -> publish id=0, zero bbox, score=0, quality=0
```

Detailed internal state remains available through:

```text
/target_memory/status
```

```text

```

```text

```

Observed:

```text
LOCKED -> UNCERTAIN -> LOST -> REACQUIRED -> LOCKED
```

During lost state:

```text

```

## Deterministic Fault-Injection Evaluation

Because natural ID switches are difficult to reproduce on demand, added deterministic fault injection using recorded `/tracks`.

### Single-case evaluation

Script:

```text
tools/analysis/evaluate_tim_v0_fault_injection.py
```

Fault model:

```text
selected target ID disappears for N seconds
same target reappears under replacement ID
```

Single-case result on `tim_v0_occlusion_01`:

```text
selected ID: 1
replacement ID: 3
gap start: 28.0 s
gap duration: 2.0 s
```

Results:

```text
Raw ID selector valid after fault: 0/110
TIM-V0 valid after fault:        85/110
TIM reacquisition time:          0.01 s
Reacquired ID:                   3
Quality:                         0.825
Reason:                          reacquired_candidate
```

Interpretation:

The raw selected-ID baseline failed completely because it continued waiting for the original tracker ID. TIM-V0 recovered the selected target under the replacement ID using memory and geometric consistency.

### Batch evaluation

Added:

```text
tools/analysis/evaluate_tim_v0_fault_injection_batch.py
```

Batch configuration:


### Failure analysis

Added failure diagnostics for unrecovered cases.

Failed cases:

```text
gap start = 32.00 s, duration = 2.00 s
gap start = 32.00 s, duration = 3.00 s
```

Failure reason:

```text

```

Interpretation:

TIM-V0 was conservative after loss. It rejected weak geometric matches instead of risking a wrong reacquisition. This is an honest operating limit and motivates TIM-V1 appearance support.

## Final Interpretation

TIM-V0 provides a valid selected-target memory baseline for the thesis.

It does not claim to solve all identity tracking. Instead, it shows that a lightweight memory layer above detector and tracker outputs can:

- preserve selected-target semantics better than raw tracker ID selection
- expose control-valid target states
- recover from deterministic tracker ID reassignment
- remain computationally negligible
- provide clear failure modes for the next novelty stage

This is a strong foundation for TIM-V1, where lightweight appearance cues can be added only when V0 geometry is insufficient.
