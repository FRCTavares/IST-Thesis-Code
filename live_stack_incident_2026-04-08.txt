Live Stack Incident Report
Date: 2026-04-08
Host: fcstpi
Repo: Thesis-Code

Summary
A hard power loss during runtime left the live stack unable to start. The startup initially failed at inference service readiness (port 5556). After driver recovery, inference came back, then camera initialization failures became the new blocker.

Initial Errors Observed
1) Live stack startup timeout on inference port
- Error: timeout waiting for required port 127.0.0.1:5556
- Location: tools/start_live_stack.sh during detection service startup in container

2) Detection service failed inside container
- Log (/tmp/detection_zmq_live.log):
  - HAILO_DRIVER_NOT_INSTALLED
  - Failed listing hailo devices
- Effect: container process never bound port 5556

3) Missing Hailo device and module on host
- /dev/hailo* did not exist
- lsmod showed no hailo module loaded
- modprobe errors:
  - Module hailo_pci not found in directory /lib/modules/6.8.0-1051-raspi

Root Cause
Kernel/module mismatch after update/reboot:
- Running kernel: 6.8.0-1051-raspi
- DKMS Hailo module existed only for: 6.8.0-1050-raspi
- Therefore no loadable hailo_pci module for current kernel and no /dev/hailo0

Solutions Applied
1) Verified and recovered Hailo DKMS for current kernel
- Installed matching headers:
  sudo apt-get install -y linux-headers-$(uname -r) dkms
- Rebuilt modules:
  sudo dkms autoinstall -k $(uname -r)
- Loaded module:
  sudo modprobe hailo_pci
- Verified:
  - lsmod showed hailo_pci loaded
  - /dev/hailo0 present

2) Restarted inference container
- docker restart pi-ai-kit-ubuntu-hailo-ubuntu-pi-1
- Result: detection service port 5556 became reachable

3) Patched camera node for device re-enumeration robustness
File changed:
- ros2_ws/src/thesis_bringup/thesis_bringup/nodes/camera_capture_node.py

Changes made:
- Added fallback auto-detection for camera device when configured /dev/video0 is missing.
- Made missing sensor subdevice non-fatal:
  - If /dev/v4l-subdev2 is absent, continue startup with warning.
  - Skip trigger_mode command when subdevice node does not exist.

Build applied:
- colcon build --packages-select thesis_bringup --symlink-install

Post-Fix Results
- Inference stage: fixed
  - [ok] port 127.0.0.1:5556 is reachable

- Camera stage: progressed but still unstable
  - Camera now falls back from /dev/video0 to /dev/video24
  - Media-ctl commands report topology/format errors on /dev/media0:
    - Invalid argument
    - No such file or directory
  - Camera node starts, but live stack still exits with camera publication timeout in some runs.

Current Status
- Primary container/driver failure resolved.
- Remaining issue is camera pipeline/media topology mismatch after the crash/re-enumeration, not Hailo inference.

Recommended Next Steps
1) Reboot host once to reset CSI/media graph cleanly.
2) Re-run ./tools/start_live_stack.sh.
3) If camera still fails:
   - Inspect media topology with: media-ctl -d /dev/media0 -p
   - Confirm correct sensor/csi entity names and pad indices for this boot.
   - Update camera bringup parameters if entity names changed.

Follow-up Resolution Addendum
Date: 2026-04-09

What was discovered after repeated failures

1) Inference and camera failures were separate
- Inference failure (port 5556 down) was fixed by restoring Hailo driver/module.
- Camera remained broken even after inference recovered.

2) Camera failure signature on broken boots
- `./tools/start_live_stack.sh` failed waiting for `/camera/image_raw`.
- `camera_capture_node` crashed with:
  - configured `/dev/video0` missing
  - selected media device exposed no camera video nodes
- `ls -l /dev/v4l-subdev*` returned none.
- `media-ctl -d /dev/media* -p` showed only `rp1-cfe` with `csi2 + pisp-fe`, and `pispbe`/`rpivid`; no TEVS sensor entity in active graph.

3) Kernel-level clues
- Logs showed TEVS DT node path discovered (`tevs@48`) and `rp1-cfe ... found subdevice ... tevs@48`.
- On some boots, also saw `pca953x ... failed writing register`/probe errors; on later boots this specific error disappeared but camera still did not bind into V4L2.

4) Actual root cause for persistent camera failure on current kernel
- Running kernel: `6.8.0-1051-raspi`.
- TEVS module existed for older kernels (`6.8.0-1048`, `6.8.0-1050`) but not for `6.8.0-1051`.
- Result: overlay could declare TEVS node, but no sensor driver binding -> no `/dev/v4l-subdev*` -> no capture node -> no `/camera/image_raw`.

5) Confirmed local recovery path that worked
- Local out-of-tree TEVS source was available at: `/home/francisco/tevs-oot`.
- Rebuilt `tevs.ko` against current kernel headers (`6.8.0-1051-raspi`).
- Installed module under `/lib/modules/$(uname -r)/extra/`, ran `depmod`, loaded with `modprobe tevs`.
- After module install/load, camera graph and startup recovered.

Exact commands used for TEVS module recovery

```bash
cd /home/francisco/tevs-oot
make clean
make -j$(nproc)

sudo mkdir -p /lib/modules/$(uname -r)/extra
sudo cp /home/francisco/tevs-oot/tevs.ko /lib/modules/$(uname -r)/extra/tevs.ko
sudo depmod -a
sudo modprobe -r tevs 2>/dev/null || true
sudo modprobe tevs
```

Verification commands after TEVS install

```bash
uname -r
ls -l /dev/v4l-subdev*
media-ctl -d /dev/media0 -p
media-ctl -d /dev/media1 -p
v4l2-ctl --list-devices
./tools/start_live_stack.sh
```

Expected good state
- `/dev/v4l-subdev*` exists.
- A media graph includes TEVS sensor entities and camera capture path.
- `start_live_stack` passes camera readiness and `/camera/image_raw` publishes.

Safety notes for future incidents

1) Avoid risky remote boot config changes first
- Do not immediately pin/change kernel/initramfs lines in `/boot/firmware/config.txt` over remote shell; this caused a temporary lockout once.
- Prefer module rebuild/install for the current kernel when possible.

2) Fast triage checklist
- `uname -r`
- `modinfo tevs` (or check `/lib/modules/$(uname -r)/extra/tevs.ko`)
- `ls -l /dev/v4l-subdev*`
- `media-ctl -d /dev/media0 -p`
- `journalctl -k -b --no-pager | rg -i "tevs|rp1-cfe|pca953x|i2c|fail|error"`

3) If TEVS module missing for current kernel
- Rebuild/install TEVS OOT module for that kernel before changing camera node code.

Repository changes made during this incident window

- `tools/start_live_stack.sh`
  - Added camera log fatal-error detection and clearer startup diagnostics.
  - Added media graph auto-detection preflight and explicit hints when no camera entities are present.

- `ros2_ws/src/thesis_bringup/thesis_bringup/nodes/camera_capture_node.py`
  - Improved media-device selection to avoid false fallback onto non-camera `pispbe` nodes.
  - Added fail-fast behavior when selected media graph exposes no video nodes.
